# SOW-0001: テスト項目・実行履歴のCSVインポート／エクスポート

- 作成日: 2026-11-26
- 関連: [ADR-0001](../adr/0001-csv-import-export.md)（方式の決定）、[要件定義 4.8](../requirements.md)

## 1. 背景と目的

テスト項目と実行結果をExcelで一括編集・共有し、ポータルへ戻せるようにする。
これにより、現行Excelからの移行（要件定義 4.8）と、手作業の一括更新を画面から行えるようにする。

## 2. 対象範囲

### 2.1 対象
| # | 機能 | 内容 |
|---|---|---|
| F1 | テスト項目エクスポート | アプリのテスト項目をCSVで出力（無効なケースを含めるか選択） |
| F2 | テスト項目インポート | CSVを取り込み、`case_key` で照合して新規作成・更新 |
| F3 | 実行履歴エクスポート | 実行回と結果をCSVで出力（開始日時の期間・実行回で絞り込み） |
| F4 | 実行履歴インポート | CSVを取り込み、既存実行回の結果・実行情報の更新と、新規実行回の作成 |
| F5 | 画面 | ケース一覧・実行履歴画面の出力ボタンと、取り込み画面（事前確認 → 反映） |
| F6 | ドキュメント・検証 | API仕様、README、要件定義の更新、単体テスト・スモーク・ブラウザー検証 |

### 2.2 対象外
- CSV以外の形式（JSON、xlsx）
- 別アプリ・別環境への取り込み（環境移行はバックアップ／復元で行う）
- 添付ファイルの取り込み・出力（後続フェーズ。別ADRで方式を決める）
- 編集履歴（`edit_history`）とケーススナップショットの出力・取り込み
- CSVに含まれないケース・実行回・結果の無効化・削除
- MCPツールへの追加

## 3. 仕様

共通事項（文字コード、日時、値の表記、数式インジェクション対策、ファイル名）は ADR-0001 に従う。

### 3.1 ファイル名
`<アプリ名>_<種別>_<YYYYMMDD_HHMMSS>.csv`（日時は出力時刻、`EXPORT_TZ`、既定 `Asia/Tokyo`）

- 例: `サンプルアプリ_テスト項目_20261126_153000.csv`、`サンプルアプリ_実行履歴_20261126_153000.csv`
- アプリ名中の使えない文字は `_` に置換。`Content-Disposition` に `filename*=UTF-8''...` と ASCII の代替名を併記する。

### 3.2 テスト項目CSV
| 列 | 必須 | 取り込み | 備考 |
|---|---|---|---|
| `case_key` | ○ | 照合キー | アプリ内で一意。ファイル内の重複はエラー |
| `category` | | ○ | |
| `title` | ○ | ○ | |
| `precondition` | | ○ | |
| `steps` | ○ | ○ | 改行はCSVのクォートで保持 |
| `expected_result` | ○ | ○ | |
| `test_type` | ○ | ○ | `manual`/`automated`/`both`、または 手動/自動/両対応 |
| `sort_order` | | ○ | 整数 |
| `is_active` | | ○ | `true`/`false`（`1`/`0`、`有効`/`無効` も可） |
| `updated_at` | | 無視 | 出力専用 |

- 任意列がヘッダーにない場合、既存ケースは現在値を維持し、新規ケースは既定値（空、`0`、有効）とする。
- 内容が変わらない行は「変更なし」とし、編集履歴を増やさない（既存 `upsertCaseByKey` と同じ挙動）。

### 3.3 実行履歴CSV（1行 = 1結果）
| 列 | 区分 | 取り込み | 備考 |
|---|---|---|---|
| `run_id` | 実行回 | 照合キー | 既存実行回のID。新規は `NEW-` で始まる任意ラベル（同じラベルの行が1実行回） |
| `run_type` | 実行回 | 新規のみ | `manual`/`automated`（手動/自動も可）。既存実行回で値が異なればエラー |
| `started_at` | 実行回 | 新規のみ | 既存実行回で値が異なればエラー。新規で空なら取り込み時刻 |
| `finished_at` | 実行回 | ○ | `started_at` 以降 |
| `runner_name` / `executed_by` / `app_version` / `device_name` / `android_version` | 実行回 | ○ | |
| `run_notes` / `run_summary` | 実行回 | ○ | `test_runs.notes` / `summary` |
| `case_key` | 結果 | 照合キー | 既存実行回では、その実行回に含まれるケースのみ。新規では有効なケースのみ |
| `case_title` | 結果 | 無視 | 出力専用（実行時スナップショットの名称） |
| `status` | 結果 | ○ | `not_run`/`passed`/`failed`/`blocked`（未実施/成功/失敗/保留も可） |
| `actual_result` / `comment` | 結果 | ○ | |
| `attachment_count` / `result_updated_at` | 結果 | 無視 | 出力専用 |

- 同じ実行回の行の間で実行回の列が食い違う場合はエラー。
- 1実行回の中で同じ `case_key` が重複する場合はエラー。
- 既存実行回の実行情報の更新は `PATCH /api/runs/:id` と同じ制約（実行方法・開始日時・ケース構成は変更不可）。
- 新規実行回は `POST /api/apps/:app/runs` と同じく、取り込み時点のケース定義をスナップショットとして保存する。
- 既存実行回に含まれない結果は変更しない（CSVに一部のケースだけ書いてもよい）。

### 3.4 API
| メソッド・パス | 内容 |
|---|---|
| `GET /api/apps/:app/cases/export` | `?include_inactive=true\|false`（既定 true） |
| `POST /api/apps/:app/cases/import` | multipart `file`、`changed_by`。`?dry_run=true` で事前確認 |
| `GET /api/apps/:app/runs/export` | `?from=&to=`（開始日時、日付）、`?run_ids=1,2` |
| `POST /api/apps/:app/runs/import` | multipart `file`、`changed_by`。`?dry_run=true` で事前確認 |

取り込みの応答（事前確認・反映とも同じ形）:

```json
{
  "dry_run": true,
  "summary": { "created": 3, "updated": 5, "unchanged": 40, "errors": 1 },
  "rows": [
    { "line": 12, "key": "LOGIN-001", "action": "updated", "changes": { "title": ["旧", "新"] } },
    { "line": 18, "key": "LOGIN-009", "action": "error", "error": "test_type が不正です" }
  ]
}
```

- エラーが1件でもあれば反映時は 422 を返し、何も書き込まない。
- 上限: 5MB・5000行（データ行）。超過時は 413／400。
- 編集履歴の `reason` は「CSVインポート: <ファイル名>」、`changed_by` はリクエストの値。

### 3.5 画面
- ケース一覧: 「CSV出力」（無効を含むか選択）、「CSV取り込み」。
- 実行履歴: 「CSV出力」（既存の日付フィルターの期間を引き継ぐ）、「CSV取り込み」。
- 取り込みダイアログ: ファイル選択 → 事前確認の集計とエラー行・差分の表 → エラーがなければ「反映」→ 結果表示と一覧の再読み込み。

## 4. 作業内容とフェーズ

### フェーズ1: テスト項目（F1, F2 と関連する F5, F6）
1. `upsertCaseByKey` の処理を `upsertCase(ctx, tx, app, input)` に切り出し、既存APIとインポートで共用する。
2. CSV共通処理（`backend/csvio.go`）: 文字コード判定（UTF-8/CP932）、BOM、ヘッダー解析、数式エスケープとその解除、日時・真偽値・表示名の変換、ファイル名生成。
3. エクスポート・インポートAPI（`backend/cases_csv.go`）。
4. 画面（出力ボタン、取り込みダイアログ）。
5. Go単体テスト（`csvio_test.go`）、`scripts/smoke.py` の往復テスト、ブラウザー検証。

### フェーズ2: 実行履歴（F3, F4 と関連する F5, F6）
1. 実行回作成・結果更新・実行情報更新の処理を、トランザクションを受け取る関数として共通化する。
2. エクスポート・インポートAPI（`backend/runs_csv.go`）。
3. 画面、テスト。

### フェーズ3（後続・別途合意）: 添付ファイル
CSVと添付をまとめた一括取り込み・出力の方式を別ADRで決定してから着手する。

### 各フェーズ共通
- `docs/api.md`、`README.md`（実装済み一覧）、`docs/requirements.md` 4.8 を更新する。
- `develop` ブランチで作業する。

## 5. 受け入れ基準
1. 出力したCSVをExcelで開いて文字化けせず、改行を含むセルが1セルとして表示される。
2. 出力したCSVを編集せずに取り込むと、全行が「変更なし」になり、編集履歴が増えない。
3. Excelで編集し「CSV UTF-8」「CSV（コンマ区切り、Shift_JIS）」のどちらで保存しても取り込める。
4. 事前確認では、DBが変わらず、行ごとの新規／更新／変更なし／エラーと差分が表示される。
5. エラー行を含むCSVを反映しても、何も書き込まれない。
6. 更新されたケース・結果に「CSVインポート: <ファイル名>」の編集履歴が残る。
7. `=SUM(1)` などで始まる値を出力したCSVをExcelで開いても数式として実行されず、取り込み後の値は元と同じになる。
8. ファイル名が `<アプリ名>_<種別>_<YYYYMMDD_HHMMSS>.csv` で、日本語のアプリ名でもブラウザーで正しく保存される。
9. 実行履歴CSVで、`NEW-` ラベルの行から新しい実行回が作られ、スナップショットは取り込み時点のケース定義になる。
10. 既存実行回の `run_type`・`started_at` を変えたCSV、実行回に含まれない `case_key` を書いたCSVはエラーになる。
11. 単体テスト、`scripts/smoke.py`、`npm run test:e2e` がすべて成功する。

## 6. 前提・制約
- 認証がないため、`changed_by` は自己申告の値とする（既存APIと同じ）。
- 事前確認から反映までの間に他の人が変更した場合、反映時の状態で再判定する。結果は反映の応答で確認する。
- CSVは完全なバックアップではない（編集履歴・スナップショット・添付を含まない）。

## 7. リスクと対策
| リスク | 対策 |
|---|---|
| Excelが日時・数値の形式を変えて保存する | 日時は複数形式を受け付ける。`case_key` 等が数値化されて先頭の0が消える点は、ドキュメントで「文字列として開く」手順を案内する |
| 大きなCSVで処理が長時間になりロックが続く | 5000行の上限。超える場合は分割を案内する |
| 文字コードの誤判定 | UTF-8として妥当かを先に判定する。事前確認の差分で文字化けに気づけるようにする |
| 取り込みによる意図しない上書き | 事前確認を必須の手順とし、差分を表示する。編集履歴から復元できる |

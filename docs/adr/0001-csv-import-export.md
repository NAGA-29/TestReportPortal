# ADR-0001: テスト項目・実行履歴のインポート／エクスポートをCSVに統一する

- ステータス: 承認済み
- 日付: 2026-11-26（同日改訂: Shift_JISは拒否、日時はブラウザーのタイムゾーン、取り込みは内部コードのみ）
- 関連: [SOW-0001](../sow/0001-import-export.md)、[要件定義 4.8](../requirements.md)

## コンテキスト

現行のテスト管理はExcelで行われており、要件定義 4.8 で「Excelからの移行」と「出力の必要性確認」が挙がっている。
ポータルのデータをExcelで編集・共有し、ポータルへ戻す手段が必要になった。

検討時点の前提:

- テスト項目はアプリ単位で `case_key` により一意（`UNIQUE(app_id, case_key)`）。キー指定のupsertと編集履歴の記録は実装済み。
- 実行結果は実行時点のケース定義を `case_snapshot` に保持し、変更履歴を `edit_history` に残す。
- 環境間の完全な移行は `scripts/backup.sh`（pg_dump + 添付tar）で既に可能。
- 当初案ではJSON（完全往復用）とCSV（編集用）の併用、実行履歴は別アプリへの取り込みも想定していた。

## 決定

### 1. 形式はCSVのみとする
テスト項目・実行履歴とも、取り込み・出力の形式をCSVに統一する。JSON・xlsxは提供しない。

- 利用者がExcelで直接開いて編集し、そのまま戻せることを最優先する。
- 形式を1つに絞り、実装・検証・ドキュメントの量を抑える。

### 2. 取り込みは同一アプリ（同一環境）への再取り込みのみ対応する
別アプリ・別環境への取り込みは対象外とする。環境移行はバックアップ／復元で行う。

- テスト項目は `case_key` で照合する（存在すれば更新、なければ新規）。
- 実行履歴は既存の `run_id`（`test_runs.id`）で照合する。新規の実行回は `run_id` 欄に `NEW-1` のような `NEW-` で始まる任意のラベルを書き、同じラベルの行を1つの実行回としてまとめる。
- このため、実行回に外部用の一意ID（`export_uid` 等）を追加するスキーマ変更は行わない。

### 3. 1ファイル1表・1行1レコード
- テスト項目CSV: 1行 = 1ケース。
- 実行履歴CSV: 1行 = 1結果。実行回の列（実行方法・端末等）は同じ実行回の行に繰り返し記載する。
  同じ実行回の行の間で実行回の列の値が食い違う場合はエラーとする。
- 出力専用の参考列（ケース名、添付件数など）は、取り込み時に無視する。

### 4. 取り込みは「事前確認 → 反映」の2段階、全件1トランザクション
- 事前確認（dry run）は行ごとに 新規／更新／変更なし／エラー と差分を返し、DBに書き込まない。
- 反映は全行を1トランザクションで処理し、1行でもエラーがあれば全体を取り消す。
- 変更は既存の編集履歴に記録する（`reason` に「CSVインポート: <ファイル名>」）。変更のない行は履歴を増やさない。
- CSVに含まれないケース・実行回・結果は変更しない（無効化・削除はしない）。

### 5. 文字コード
- 出力: UTF-8（BOM付き）。Excelでダブルクリックして開いても文字化けしないようにする。
- 取り込み: UTF-8（BOMの有無を問わない）のみ受け付ける。UTF-8として不正なバイト列を含むファイルは、
  「UTF-8で保存してください（Excelでは『CSV UTF-8（コンマ区切り）』）」というエラーで全体を拒否する。
  Shift_JIS等を推測して変換すると誤判定で文字化けしたまま取り込まれる危険があるため、変換は行わない。

### 6. 日時
サーバーは特定のタイムゾーン（日本時間など）を前提にしない。DBの値はUTCのまま扱い、
表示・入力のタイムゾーンはブラウザーの設定（`Intl.DateTimeFormat().resolvedOptions().timeZone`）に従う。

- 画面からの出力・取り込みでは、ブラウザーがIANAタイムゾーン名を `tz` パラメーターで送る。
  サーバーはその地域時間で `YYYY-MM-DD HH:MM:SS` を書き出し、取り込み時はタイムゾーンのない値をその地域時間として解釈する。
- `tz` が省略された場合（APIの直接利用など）はUTCとする。不正なタイムゾーン名は400エラー。
- 取り込みでは `YYYY-MM-DD HH:MM[:SS]`、`YYYY/MM/DD HH:MM[:SS]`（Excelで再保存した場合）、RFC 3339（オフセット付き）を受け付ける。
- タイムゾーン情報はコンテナのOSに依存しないよう、Goの `time/tzdata` を組み込む。

### 7. 値の表記
- ヘッダー行は英語のフィールド名（APIのJSONキーと同じ）とする。列の順番は自由。未知の列はエラーにする。
- テスト方法・実行方法・結果は、内部コード（`manual` / `automated` / `both`、`not_run` / `passed` / `failed` / `blocked`）で出力し、
  取り込みも内部コードのみ受け付ける。画面の表示名（手動、成功 など）はエラーとする。
  日本語の表示名との変換は行わず、CSVの値をAPI・DBの値と一致させる。
- 有効フラグは `true` / `false` のみとする。

### 8. CSVの数式インジェクション対策
- 出力時、値が `=` `+` `-` `@` タブ・CRで始まるセルの先頭に `'` を付ける（OWASPの推奨に従う）。
- 取り込み時、`'` の直後が上記の文字であれば `'` を取り除く。これで往復しても値が変わらない。
- 制約: 元の値自体が `'=` のように始まる場合は、往復で先頭の `'` が失われる。実運用上は許容する。

### 9. ファイル名
`<アプリ名>_<種別>_<YYYYMMDD_HHMMSS>.csv`（日時は出力時刻。6. と同じくブラウザーのタイムゾーン、省略時UTC）

- 例: `サンプルアプリ_テスト項目_20261126_153000.csv`、`サンプルアプリ_実行履歴_20261126_153000.csv`
- アプリ名からOSでファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）を `_` に置換し、前後の空白・ピリオドを除き、最大80文字に切り詰める。空になれば `app<ID>` とする。
- `Content-Disposition` に、RFC 6266／5987形式の `filename*=UTF-8''...` と、ASCIIのみの `filename=` 代替（`app<ID>_test-cases_<日時>.csv` など）を併記する。

### 10. 添付ファイル
CSVには添付を含めない（出力専用の添付件数列のみ）。添付を含む一括取り込み・出力（CSV + 添付をまとめたZIP等）は後続フェーズで別ADRとして決定する。

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| JSONとCSVの併用 | 完全な往復はバックアップ／復元で足り、形式を2つ保守する利点が小さい |
| Shift_JIS（CP932）も自動判定して受け付ける | 判定を誤ると文字化けしたまま取り込まれる。エラーにしてUTF-8での保存を案内する方が安全 |
| 日時をサーバー側で日本時間に固定 | 利用者の地域・端末設定と食い違う。表示は画面と同じくブラウザーの設定に合わせる |
| 取り込みで日本語の表示名も受け付ける | 変換表の保守が必要になり、CSVとAPIの値が二重になる |
| xlsx | 依存ライブラリが増え、セル書式・型の揺れへの対応が必要。CSVで要件を満たせる |
| 実行回に `export_uid` を追加し、別環境・別アプリへの取り込みに対応 | 同一アプリへの再取り込みのみが要件であり、スキーマ変更とID照合の複雑さに見合わない |
| CSVにないケースを自動で無効化 | 一部だけのCSVを取り込んだときに意図しない無効化が起きる |
| 行ごとにコミット（部分成功） | 途中までの反映状態が生まれ、再取り込みの判断が難しくなる |

## 結果（影響）

- 利用者はExcelでテスト項目・実行結果を一括編集し、差分を確認してから戻せる。
- 実行結果の編集履歴（`edit_history`）・ケーススナップショット・添付はCSVに含まれないため、CSVは完全なバックアップにはならない。完全な保全はバックアップ／復元で行う。
- 既存の1件ずつのAPI（`upsertCaseByKey`、結果更新）と同じ検証・履歴記録の処理を共通化して使う。
- 取り込み上限（5MB・5000行）を超えるデータは分割して取り込む必要がある。

# 利用ガイド

Android Test Report Portal は、Androidアプリの手動テストと自動テストの結果を、ひとつの台帳に記録するローカルWebアプリです。
このページでは、画面での基本的な使い方を順に説明します。

## 全体の流れ

1. **アプリを登録する** — テスト対象のAndroidアプリを追加します。
2. **テスト項目を登録する** — 手順と期待結果を持つテストケースを作ります。
3. **テスト実行を作成する** — 端末やバージョンを記録して、実行回を始めます。
4. **結果を記録する** — 各項目に「成功／失敗／保留」と実際の結果、証跡ファイルを残します。
5. **振り返る** — テスト一覧で直近2回の結果を比べ、履歴やCSVで共有します。

## 画面の構成

- **左のサイドバー**
  - 「対象アプリ」で表示するアプリを切り替えます。
  - 「＋ アプリを追加」で新しいアプリを登録します。
  - 「テスト一覧」「実行履歴」「ドキュメント」で表示を切り替えます。数字は有効なテスト項目数と実行回数です。
- **右のメイン領域** — 選んだアプリの情報、結果の集計（未実施・成功・失敗・保留）、一覧が表示されます。

## 1. アプリを登録する

1. サイドバーの「＋ アプリを追加」を押します。
2. アプリ名（必須）、パッケージ名、現在のバージョン、説明を入力して保存します。

登録後は、画面上部の「アプリ情報を編集」から内容を変更できます。
「現在のバージョン」は、テスト実行を作成するときのアプリのバージョンの初期値になります。

## 2. テスト項目を登録する

「テスト一覧」で「＋ テスト項目を追加」を押し、次の内容を入力します。

| 項目 | 説明 |
|---|---|
| 識別子 | アプリ内で一意なキー（例 `LOGIN-001`）。CSVやMCPでの照合に使います |
| カテゴリ | 画面や機能のまとまり（任意） |
| テスト項目名 | 一覧に表示される名前 |
| 事前条件 | テスト前に満たしておく状態（任意） |
| 手順 | 実施する操作。1行に1手順を書くと見やすく表示されます |
| 期待結果 | 正しい場合に得られる結果 |
| テスト方法 | 手動／自動／手動・自動 |
| 変更者・編集理由 | 編集履歴に残す情報（任意） |

各行の操作ボタン：

- **編集** — 内容を変更します。変更前後は編集履歴に記録されます。
- **履歴** — その項目の編集履歴を表示します。
- **無効化／有効化** — 使わなくなった項目を無効化します。削除はされず、「無効な項目も表示」にチェックすると再表示・再有効化できます。

テスト項目名を押すと、その項目の過去の結果をまとめて確認できます。

## 3. テスト実行を作成する

画面右上の「＋ テスト実行を作成」を押し、実行の環境情報を入力します。

- 実行方法（手動／自動）、実行ツール（Maestro など）
- アプリのバージョン、端末名、Android版、実行者
- 開始日時（省略すると現在日時）、補足

作成すると、**有効なテスト項目すべて**を含む実行回ができ、「実行履歴」タブにその詳細が開きます。
各結果は作成時点のテスト項目の内容（手順・期待結果）を保存するため、あとからテスト項目を編集しても過去の実行内容は変わりません。

## 4. 結果を記録する

「実行履歴」で実行回のカードを選ぶと、項目ごとの結果カードが表示されます。

- **結果を記録・編集** — 結果（未実施／成功／失敗／保留）、実際の結果、コメントを入力します。
  2回目以降の編集では「変更者」「訂正理由」を残しておくと、後から経緯を追えます。
- **＋ ファイルを添付** — スクリーンショットやログを添付します。複数添付できます。
- **編集履歴・復元** — 結果の変更履歴を表示し、過去の状態に戻せます。復元操作も新しい履歴として記録されます。

添付できるファイル：

| 種類 | 形式 | 上限 |
|---|---|---|
| 画像 | PNG / JPEG / WebP | 10MB |
| ログ等 | テキスト（.txt / .log）/ JSON / XML | 20MB |
| アーカイブ | ZIP | 50MB |
| 動画 | MP4 | 100MB |

画像はその場で表示され、テキスト系はプレビュー、動画はプレーヤーで再生できます。いずれもダウンロードできます。

## 5. 結果を振り返る

- **テスト一覧** — 「最新の結果」「前回の結果」に直近2回の結果が並びます（実行開始日時の順）。バッジを押すとその実行回を開きます。
- **絞り込み** — テスト一覧では識別子・名前・カテゴリの検索、結果、テスト方法で絞り込めます。実行履歴では実行日と実行方法で絞り込めます。
- **集計** — 画面上部のカードに、有効な項目の最新結果の件数が表示されます。

## CSVのエクスポート・インポート

Excelなどで編集・共有するときはCSVを使います。テスト一覧・実行履歴それぞれの「エクスポート」「インポート」ボタンから操作します。

- **エクスポート** — 表示中のタブの内容をCSV（UTF-8、BOM付き）で保存します。ファイル名はアプリ名と出力日時です。
  - テスト一覧は「無効な項目も表示」の状態、実行履歴は実行日のフィルターが反映されます。
- **インポート**
  1. CSVファイルを選び、必要なら変更者を入力します。
  2. まず **事前確認** を行い、新規・更新・変更なし・エラーの件数と行ごとの差分を確認します。
  3. 問題がなければ **反映** します。1行でもエラーがあると、全体が反映されません。
- **注意点**
  - 取り込めるのはUTF-8のCSVのみです。Excelでは「CSV UTF-8（コンマ区切り）」で保存してください。
  - 日時はブラウザーのタイムゾーンとして扱います。
  - テスト項目は識別子で照合します（あれば更新、なければ新規）。
  - 実行履歴で新しい実行回を作るときは、`run_id` 欄に `NEW-1` のようなラベルを書きます。同じラベルの行がひとつの実行回になります。
  - CSVに含まれない項目は変更・削除されません。

## 自動テスト・AIエージェントからの登録

- **API** — 自動テストからは構造化APIで実行回・結果を登録できます。詳しくはリポジトリの `docs/api.md` を参照してください。
- **MCPサーバー** — Claude Code などのAIエージェントは `mcp/` のMCPサーバーから、実行回の作成 → 結果登録 → 添付 → 終了を行えます。導入方法は `docs/mcp.md` を参照してください。

## 運用

- **起動・停止** — リポジトリのディレクトリで `docker compose up -d --build` で起動、`docker compose down` で停止します（データは保持されます）。`docker compose down -v` はDBと添付を削除するので通常は使いません。
- **バックアップ** — `bash scripts/backup.sh` で `.local/backups/<日時>` にDBと添付を保存します。復元手順は README を参照してください。
- **セキュリティ** — 現在はログイン機能がありません。ローカル（127.0.0.1）でのみ利用し、共有・外部公開する前に認証を追加してください。

## よくある質問

**Q. テスト項目を削除したい**
A. 削除機能はありません。「無効化」すると一覧や新しい実行回の対象から外れます。過去の結果は保持されます。

**Q. 実行回に一部の項目だけ含めたい**
A. 画面から作成すると有効な項目すべてが対象になります。一部だけにしたい場合は、APIの `case_ids` やMCPの `start_run` の `case_keys` で指定してください。

**Q. 結果を間違えて記録した**
A. 「結果を記録・編集」で訂正するか、「編集履歴・復元」から以前の状態に戻せます。どちらも履歴に残ります。

**Q. CSVが文字化けする／取り込めない**
A. UTF-8で保存し直してください。Shift_JISのCSVは取り込めません。
